# Project Reflection: Production-Grade Customer Support AI Agent

One important design choice in this project was to use Amazon Bedrock AgentCore with a modular tool-based architecture. Instead of relying on the language model to answer every question from its own knowledge, the agent uses specialized tools for knowledge-base retrieval, order tracking, refunds, loyalty calculations, and live browser access. This approach makes the system more useful for customer support because each task can use the appropriate data source or execution environment. I also used a memory hook to retrieve relevant customer context before responding and save interactions afterward, allowing the agent to provide continuity across sessions.

One of the main challenges was integrating the Gateway-backed refund functionality and ensuring that the deployed agent returned a meaningful result. Initially, the refund tool returned demonstration statuses rather than the expected approval result. I traced the issue to the Lambda function configured for the Gateway target, corrected its response behavior, packaged and redeployed the updated function, and tested the workflow through the deployed AgentCore runtime. The successful test returned an approved refund status, a refund identifier, and the requested amount while clearly stating that no real payment had been processed.

I also checked the loyalty calculation outputs and Gateway error handling to make the agent more robust. Finally, I tested the major capabilities and collected screenshots as evidence. This project taught me that building a production-oriented AI agent involves more than writing prompts: tool integration, memory management, failure handling, deployment verification, and clear testing evidence are all essential parts of a reliable system.
