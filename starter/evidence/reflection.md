# Project Reflection: Production-Grade Customer Support AI Agent

One important design decision in my project was integrating Amazon Bedrock AgentCore Gateway with both an API target for order tracking and a Lambda target for refund processing. I chose this approach to keep customer-support capabilities modular and allow the agent to use different backend integrations through a consistent tool interface. I also kept the MCP client session open while the agent was running so the tools remained available during invocation.

One concrete challenge I encountered was deployment packaging. The initial deployment package exceeded the 250 MB limit. I investigated the packaging process and identified a platform-specific dependency resolution issue in the toolkit. I adjusted the dependency compilation to target the appropriate Linux ARM64 platform, corrected the packaging workflow, and reduced the package size to approximately 101.63 MB. I then deployed the agent and verified that it could be invoked successfully.

Production reliability, security, and monitoring are important considerations for this agent. For example, refund processing must not be treated as a simple conversational response in a real customer-support system. The backend should validate order ownership, enforce authorization, prevent duplicate refund requests, and require appropriate safeguards before processing a payment-related action. In this project, the refund integration returned a demo approval response and did not process a real payment.

Monitoring is also essential. Amazon CloudWatch logs can help identify invocation failures, tool errors, and latency issues. Tracking these metrics would help diagnose problems and improve reliability as usage increases. In addition, customer memory should use consistent customer identifiers and appropriate access controls to prevent information from one customer being exposed to another.

This project helped me understand that building a production-oriented AI agent involves more than connecting a language model to tools. Reliable deployment, secure integrations, error handling, monitoring, and evidence-based testing are all necessary to make an agent dependable in a real-world environment.
